# QingheApp 项目说明

> 状态：需求基线与开发规划，基础 Flutter 工程已经建立，业务功能尚未实现。  
> 整理日期：2026 年 11 月 21 日。

QingheApp 是面向大学生的本地课表应用，计划使用 Flutter + GetX 开发，完整适配 Windows、Linux 和安卓。产品优先解决每天查看课表的体验：界面简约、动画灵动、信息可按个人习惯组织，且无广告。

离线是应用的基本工作方式。用户无需登录本软件的账号即可在本机查看和编辑课表；主动访问学校网站导入数据，与日常离线使用分开处理。当前不建设跨设备同步服务。

## 2. 产品定位与使用场景

### 2.1 目标用户

主要服务采用学期制的大学生。课表需要表达教学周、单双周、不连续周次、不同课程节次，以及调课和补课。通用培训排班、中小学课表和多人协作不是当前的专门适配目标。

### 2.2 需要解决的问题

| 现有体验问题 | 本项目的产品要求 |
| --- | --- |
| 界面与动画缺乏品质 | 基于 Flutter 基础能力设计自己的扁平化简约视觉，不沿用 MD3 原始样式；动效表达状态与操作反馈 |
| 自定义能力不足 | 允许调整外观、字段展示和布局参数，并提供可直接使用的默认配置 |
| 广告影响看课 | 产品界面不加入广告 |
| 课程信息简陋 | 支持必要的课程信息，通过详情和可配置字段平衡信息量与清晰度 |
| 三端能力失衡 | 三端都能完成核心日常操作，根据触控、键鼠和窗口宽度调整交互 |

### 2.3 典型使用流程

1. 首次使用时设置学期、教学周起点和节次时间表。
2. 手动建立课程，或填写本软件提供的 CSV 模板后导入。
3. 在周课表中查看课程，打开详情查看补充信息。
4. 对某一次课进行调课或添加补课，保留其他上课安排。
5. 设置课程通知；安卓用户可将课程小组件放到桌面。
6. 再次导入时检查变更和冲突，确认后合并，保留个人配置。

上述流程的数据与合并规则按 [DESIGN.md](DESIGN.md) 设计。具体视觉风格由用户另行设计，不在本仓库文档中预先规定。

## 3. 已确认的产品决定

| 编号 | 决定 | 对开发的约束 |
| --- | --- | --- |
| D01 | 使用 Flutter + GetX | 不擅自更换应用技术方向 |
| D02 | Windows、Linux、安卓同等重要 | 核心功能不能长期仅在一个平台可用 |
| D03 | 默认离线工作 | 查看、编辑和设置不依赖网络或本软件账号 |
| D04 | 当前不做课表同步 | 不引入同步服务器、云数据库或账号体系作为运行前提 |
| D05 | 面向大学生 | 正确处理教学周和单次课程调整 |
| D06 | 自有扁平化简约风格、灵动动画 | 可复用 Material 底层交互能力，不沿用 MD3 默认导航和选中样式 |
| D07 | 自定义达到外观加内容与布局参数层级 | 不建设自由拖拽、缩放模块的布局编辑器 |
| D08 | CSV 按本软件模板填写 | 以固定格式为基础，不优先兼容任意外部表格格式 |
| D09 | 重新导入先预览再合并 | 保留配色、备注和提醒，时间地点等冲突由用户选择 |
| D10 | 采用普通课程通知 | 不加入持续响铃、必须手动关闭和贪睡式闹钟交互 |
| D11 | 桌面关闭窗口进入托盘，主动退出停止提醒 | 窗口关闭与进程退出必须明确区分；开机启动可设置 |
| D12 | 图片导入后续再考虑 | 当前不选定本地 OCR 或云端识别方案 |
| D13 | 教务导入暂时搁置 | 不继续尝试访问学校系统或索要登录信息 |
| D14 | 课表必须展示完整 | 默认一屏显示七天和全部已配置节次，压缩顶部和行列标题，不以裁切日期代替适配 |
| D15 | 加入日历功能 | 将本地日历从后续候选移入当前设计，待办仍后续再做 |

| 分组 | 可调整项目 | 设计约束 |

课程候选信息包含课程名、上课时间、地点、教师、节次、持续时间、校区或教学楼、周次、调停补课标记、备注和上课倒计时。关联作业及截止时间曾被讨论为候选字段，但不因此将待办模块纳入当前范围。

### 4.3 暂时搁置的学校导入

原定首个适配对象为西南科技大学，目标包括普通课表和实验课程。用户计划在 WebView 内自行登录，再从页面 HTML 或可取得的 JSON 数据中提取课程。

用户提供的实验教学公开入口是 [实践教学网站](https://sjjx.dean.swust.edu.cn)。普通教务与实验教学处于不同子域名；登录态是否共享、页面结构、实际接口和课程去重依据均未验证。不能仅凭域名关系推断单点登录或数据互通。

用户已要求暂时不研究该功能。因此保留目标和预期导入流程，不继续访问或逆向分析，不把尚未完成的适配当作当前开发阻塞项。是否恢复原定首发安排，需要后续重新明确。

## 5. 三端体验与运行边界

### 5.1 三端一致的核心能力

课程和周次规则、CSV 校验、导入合并策略与个性化设置的含义保持一致。三端共享业务规则，不要求窗口布局、导航形式和系统集成实现完全相同。

安卓以触控为主；桌面端兼顾键鼠、窗口缩放和托盘。小组件是安卓专属集成，不应为追求表面上的三端一致而强行复制到桌面平台。

### 5.2 桌面生命周期

- 关闭主窗口后进入托盘，课程通知继续运行。
- 从菜单主动退出后结束后台运行，停止本软件的桌面课程提醒。
- 开机启动由用户设置；具体默认值属于待验证的交互细节。
- 桌面环境无法提供可用托盘时，应保留可见入口并解释限制，不能把应用隐藏到用户无法恢复的位置。
- 关机、系统休眠和用户结束进程等情形不属于持续运行保证。

### 5.3 安卓提醒与小组件

课程通知和桌面小组件需要与系统调度、权限和进程生命周期衔接。普通通知指交互形式，不等于可以依靠应用内定时器保证后台准点执行。

Android 的后台任务执行时间受系统条件影响，提醒调度需要结合平台能力验证；不能承诺强制停止、权限关闭或所有省电限制下仍准点通知。[Android 后台任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

## 6. 质量要求与验收标准

| 维度 | 验收要求 | 验证方式 |
| --- | --- | --- |
| 离线能力 | 断网时可冷启动、查看、编辑、切换周次并保存设置 | 三端断网操作并重启读取 |
| 周次正确性 | 单双周、不连续周次和学期边界结果正确 | 使用固定日期样例的单元测试 |
| 单次调整 | 调整一次课程不改变其他日期的课程 | 对比调整前后的课程实例 |
| 数据可靠性 | 导入取消和失败不留下半份课表；重复确认不重复写入 | 事务失败与重复提交场景测试 |
| 合并安全 | 未解决冲突不能提交；个人配色、备注和提醒保留 | 基于导入基线的差异样例测试 |
| 设置持久化 | 自定义重启后保留；恢复默认不影响课程数据 | 设置读写与界面测试 |
| 可读性 | 深浅模式、长课程名和字号调整后信息仍可理解 | 组件测试与真实窗口检查 |
| 动画体验 | 快速连续切换无错周、无等待锁定、无明显布局跳动 | 三端交互录屏与性能分析 |
| 系统集成 | 提醒、小组件和托盘符合已声明的运行边界 | 真实设备与目标桌面环境验证 |
| 隐私 | 示例和日志不包含个人数据或凭证 | 文档、测试数据与日志检查 |

目前未建立实测性能基线、覆盖率门槛、最低操作系统版本或发布支持矩阵。首次工程验证后再记录可复现的数据，不预填“全部支持”或性能数值。

## 7. 开发顺序与阶段交付

阶段表示建议的依赖顺序，不是承诺的日历排期。每个阶段都应保持对三端差异的关注，避免最后才发现关键平台无法实现。

| 阶段 | 主要工作 | 完成条件 |
| --- | --- | --- |
| M0 基础工程与技术验证 | 初始化三端工程，建立路由与功能分层，验证数据库、通知、托盘与小组件的最小链路 | 基础工程可分析、可测试，依赖与平台限制有验证记录 |
| M1 本地课表闭环 | 完成学期、节次、课程录入、周课表、单次调整与本地持久化 | 三端断网可完成建课到查看的完整流程 |
| M2 导入与日期查看 | 冻结 CSV 格式，完成校验、预览、合并与事务提交；加入基于现有课程的本地日历 | 导入样例得到明确处理，日历与课表显示同一份课程实例 |
| M3 个性化与体验完善 | 在已有页面基础上完成字段配置、主题、布局参数、设置预览与动效完善 | 默认配置可用，自定义可持久化，三端主要操作顺畅 |
| M4 平台集成 | 完整接入课程通知、小组件、托盘和启动设置 | 通过生命周期、权限、休眠恢复等场景验证 |
| M5 发布准备 | 回归、安装包检查、文档校对和已知限制整理 | 支持矩阵与验证证据齐全，更新日志对应实际产物 |

教务导入恢复后另行评估，不自动插入上述排期；图片、待办和同步不因预留设计而被视为已经排入开发。日历已按最新要求纳入当前规划，初期不延伸到独立事件管理或第三方日历同步。
